## Composition and edge semantics

A node is a procedure: accepting input and retained state, performing work, returning output and the next retained state. A persistent daemon repeatedly performs this procedure; a timer, failure event, boot, operator command or deployment invokes a bounded procedure. Tables distinguish these lifecycles.

An arrow means transferred data/message only. Hosting is a containment boundary, access policy constrains a transfer, and startup dependency constrains execution order; neither becomes a fictitious data arrow. Disks, databases, caches and snapshots are retained state, not running procedures. Their read/write operations appear at process boundaries. The physical machines each compose kernel networking, filesystem operations, systemd supervision and application procedures. Containers add a namespace/process supervision boundary inside Pi's OS, not another physical machine.

```text
Client resolve procedure --DNS question--> Pi DNS procedure --DNS answer--> client
Client request procedure --HTTPS request--> Pi ingress procedure
Pi ingress --verification request--> Pi identity procedure --decision/headers--> ingress
Pi ingress --HTTP request--> workstation service procedure --HTTP response--> ingress
ingress --HTTPS response--> client

Workstation service --log event--> workstation journal/Vector procedures
Vector --bulk log records--> Pi log ingestion procedure --query response--> Grafana
Pi metrics scraper --scrape request--> workstation exporter --measurements--> scraper
Gatus --probe request--> service --response--> Gatus --alert message--> external ntfy

Filesystem read --current bytes--> snapshot procedure --retained snapshot S(t+1)--> storage
Retained S(t) --historical bytes--> restore procedure --restored bytes--> scratch storage
Scratch read --verification observations--> operator procedure --approved recovery command--> recovery
```

State feedback is temporal: a retained snapshot, journal cursor, session database, DNS API record or success marker produced at time t is read by the next invocation at t+1. This is not a claim that the entire graph is acyclic. Human inspection/approval is an explicit external procedure; alerts do not automatically imply a repair command.

## Additional workstation runtime support

- Nix daemon/build procedures accept derivations, source inputs and cache responses and produce store paths. Attic seed/watch procedures publish completed store paths to the cache endpoint; cache reads feed later builds. Seed and watch are configured in `nix/modules/system/base/base.nix`; weekly GC consumes reachability/age state and removes eligible store paths. Cache is retained derivable state, distinct from independent backup.
- SOPS activation decrypts encrypted declarations to runtime secret files consumed by application startup. Credential file reads cross an access boundary; contents were not read (`nix/modules/system/base/sops.nix`, individual workload secret declarations).
- Workstation `resource-policy.nix` constrains user and Nix-daemon cgroups, including resident memory and swap. These are scheduler/resource envelopes around procedures, not messages between services. Kernel pressure and systemd supervision can change process lifecycle; configured bounds do not prove observed resource use.
- Persistent application processes may also own database/storage helpers. Their workload-local dump/read paths are inputs to backup intent; this platform inventory does not pretend to enumerate every application database transaction or media workflow, which belongs in the application process inventory.

## Model gaps and contradictions to preserve, not silently resolve

1. Adapter still generates a `station-blocky-dns` probe to workstation LAN :53 although current workload selection does not include Blocky. Its `station-caddy` probe actually requests `https://uptime.<domain>`, which current entry ownership routes through Pi. These names are not reliable process-host evidence (`pi/scripts/generate-inventory.sh:121–136`; `inventory/profiles.nix`; Nix base comment calls workstation Caddy retired).
2. Shared networking documentation still diagrams Pi Blocky, but actual production role is Pi-hole. Existing Nix adapters must not be mistaken for active Pi implementation.
3. Workstation Vector/Grafana use Pi tailnet :9428/:8428, while Pi role defaults bind services to Pi LAN address and firewall diagnostic ports refer to subnet-reachable listeners. Actual transport compatibility needs separate end-to-end verification; this read does not assume a matching tailnet listener or rewrite the declarations.
4. Pi physical journal volatility, Gatus memory state and 14-day central history have different retention boundaries. None is a general durable event log for replaying the entire homelab.
5. Disabled OneTouch policy disables new restic scheduling and receiver setup; it does not establish current live timer state or erase old copies. Live mount, old archive inventory, private credential pairing, SSH identity, free capacity and actual restore outcomes remain unknown.
6. Source comments retain older hardware/host expectations (e.g. Toshiba/family and Pi Nix-build descriptions). Executable selection and current paths take priority; full evaluated filesystem/daemon configuration was not obtained for this report.

This artifact is a descriptive source projection, not an enforcement proposal, proof, test result or deployment authorization.
