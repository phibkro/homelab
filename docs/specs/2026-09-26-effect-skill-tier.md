# Effect skill tier for /srv/share/projects

Status: frozen for implementation on 2026-09-26 (operator decisions in this session). Revised the same day by operator decision: an OMP extension package replaces the configuration and symlink plumbing of the first draft (Decision 1). Remove this specification when the checks below run and the enduring rules live in `docs/PROJECTS.md`, the skills, the profiles, and the package.

## Goal

Every agent that writes TypeScript under `/srv/share/projects` writes native Effect: it looks up the version-exact Effect guidance and examples before writing, uses an Effect construct wherever one exists, and falls back to plain TypeScript or another package only after it has established that Effect cannot express or compose the intent. Guidance teaches it; lint rules, type checks, and tests enforce it.

## Decisions

1. **Tier delivery: one OMP extension package (operator decision, replaces the first draft's `skills.customDirectories`, `/srv` links, and user `AGENTS.md` instruction).** The versioned homelab source `src/users/nori/programs/projects-tier/` is an OMP extension package: `skills/` holds the twelve primitives, `agents/` holds the four profiles, and `index.ts` is the repository-context hook. The homelab OMP module installs it declaratively: the generated `config.yml` lists the package's store path under `extensions:`. OMP discovers `<package>/skills` (omp-plugins provider) and `<package>/agents` (task-agent discovery) from that entry in every session and subagent, whatever the working directory.
2. **Instruction chain on first touch.** For `read`, `edit` (every edit mode: hashline `[PATH#TAG]` sections and their `MV` destinations, apply_patch file markers, the replace and patch modes' `path` and renames), `write`, `grep`, `glob`, `ast_grep`, and `ast_edit` calls (including the `xd://ast_grep` and `xd://ast_edit` devices), the hook maps each touched path to its git toplevel (a `.git` directory with `HEAD`, or a `.git` file with `gitdir:` for worktrees and submodules). The first time a session touches a repository, the hook injects once, as an agent-attributed aside, the chain: the user `AGENTS.md` (`<agent dir>/AGENTS.md`, once per session), `<repo>/AGENTS.md`, every ancestor `AGENTS.md` up to and including `/srv/share/projects/AGENTS.md` (only for repositories under `/srv/share/projects`), the names and descriptions of `<repo>/.agents/skills/*`, and the full text of `effect-house` when the repository has one. A file whose full text is already in the session's system prompt is named, not repeated; so a main session gets the parts its context walk missed, and a task subagent, which starts without any `AGENTS.md`, gets the whole chain. Gate: in a repository that has `effect-house`, the hook blocks a call that changes a `.ts`/`.tsx`/`.mts`/`.cts` file until the injection has been delivered (the aside's `message_end`, or the aside among a `context` event's messages), and the block reason tells the agent to read the injected context and retry. An injection that has not arrived one full turn later stops blocking, so a delivery fault cannot hold edits back for the rest of the session. The model's context is the record of what was delivered: each `context` event marks the injections it carries as delivered, an injection seen before and missing now (compaction, `/clear`, another branch) makes the next touch inject again, and a resumed session recovers its earlier injections; a new or switched session starts empty.
3. **API authority is never copied.** Skills link to the installed `node_modules/effect/AGENTS.md`, `ai-docs/src`, and source, and to the official `effect-ts` skill. They never restate API signatures; they teach decisions, composition, verification, and the project's escape-hatch discipline.
4. **Skill primitives** (portable, Effect v4, in the package's `skills/`): `effect-first` (router: establish versions, lookup order, the decision ladder, pure stays pure, done-means), `effect-domain-models`, `effect-services-layers`, `effect-errors-recovery`, `effect-resources-concurrency`, `effect-streams-protocols`, `effect-boundary-adapters`, `effect-persistence-workflows`, `effect-ui-lifetimes` (Foldkit), `effect-domain-constructs`, `effect-testing`, `effect-review-exceptions`. Seeded from the research pack's drafts, rewritten against the installed Effect 4.0.0-rc.116 guidance, with every rule linked to the enforcement that exists (an `effecttsgo/*` rule, a project rule, a test) or marked review-only.
5. **Profiles are materialized views** (in the package's `agents/`): `effect-engineering` (router + all core primitives), `effect-backend-engineering`, `effect-ui-development`, `effect-library-development`. Each is frontmatter `autoloadSkills` over primitives plus a short role prompt; each also lists `effect-house`, the convention name a repository uses for its own overlay skill (OMP ignores an unknown name, so repositories without an overlay still work). Because autoload and repository-local skill discovery depend on the parent session's working directory, every profile body starts with a by-path fallback: identify the repository; read `<repo root>/AGENTS.md`; if `<repo root>/.agents/skills/effect-house/SKILL.md` exists, read it and its references before writing code, even when it was not autoloaded. `effect-first` states the same step in its lookup order.
6. **Repository overlays** live at `<repo>/.agents/skills/effect-house/SKILL.md` and carry house conventions only (constructs, composition roots, test platform, runtime bridges, the exception registry and its check). They link to generated artifacts such as `docs/constructs.md` and do not restate the primitives. The hook injects the overlay's `SKILL.md` verbatim, so it stays lean and links to its references.
7. **Exceptions have a lifecycle.** A disable comment or a non-native substitute names a registered exception with scope, missing capability, native alternatives examined, verification, owner, and retirement trigger; retired when the native capability arrives.

## Checks (Done when)

1. After `just rebuild`, `omp -p` probes run twice, once with the working directory inside `mono-web` and once from `/srv/share/projects` above it. Each probe lists the tier skills and profiles. On its first touch of a `mono-web` file the session receives the injected repository context (`mono-web/AGENTS.md`, `/srv/share/projects/AGENTS.md`, the `.agents/skills` list, and the `effect-house` text once the overlay has landed); a task subagent that touches `mono-web` also receives the user `AGENTS.md`. Its first `.ts` edit in `mono-web` is blocked until that context has been delivered, and the retried edit succeeds. Evidence is recorded in the commit message of the change that removes this specification.
2. A homelab eval check fails when a profile's `autoloadSkills` names a tier skill that does not exist (the repository overlay name `effect-house` is the one allowed external name), and when a skill's frontmatter violates the Agent Skills format (name equals directory, description with a use-when trigger). Unit tests cover path-to-repository mapping (worktrees included), the once-per-repository injection, a subagent session that receives the whole chain on first touch, and the `.ts` gate; negative controls prove each check can fail.
3. Every skill links to the installed Effect guidance and contains no API signature restated from it (the eval check rejects TypeScript code blocks); every rule in a skill names its enforcement or says review-only (the eval check validates each rule row against the FX registry and the enforcement vocabulary).
4. `docs/PROJECTS.md` states the Effect-first clause and the lookup order.
5. `nix flake check` and the workstation build pass; nothing is deployed without the operator's `just rebuild`.
