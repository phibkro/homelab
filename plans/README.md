## Shared execution rules

Every plan inherits these repository constraints:

1. **Read before write.** Re-run the plan's drift check and compare current code with its excerpts.
2. **No secret values in output.** Encrypted-file plans may name keys and paths only. Never print values into transcripts, commits, tests, or review comments.
3. **Real boundary verification.** Security, storage, auth, network, and systemd changes require the real journey named by the plan; a green eval alone is insufficient.
4. **Do not repair live red state silently.** If a strengthened test exposes a stale backup, replica, heartbeat, or auth mismatch, stop and report before triggering jobs or changing policy.
5. **Full gate.** Unless a plan explicitly stops earlier on live-state failure, finish with `nix flake check --print-build-logs`.
6. **No push without the project push gate.** Do not push or open a PR unless the operator explicitly requests it.

## Findings considered and rejected

Recorded so a later audit does not rediscover them without new evidence:

- **“An empty backup registry silently passes.”** Rejected: with the current `set -euo pipefail` pipeline, no match exits uncontrolled rather than reporting success. Plan 006 still replaces this with an explicit diagnostic.
- **“`just test` must run all NixOS VM tests.”** Rejected: `just check` / `nix flake check` is already the complete non-interactive pre-deploy gate; live runtime tests are a separate layer.
- **“Add CI cache configuration.”** Rejected for now: no measured cold/warm CI latency or reliability problem was gathered. Measure before adding trust/configuration surface.
- **“Extract the large `flake.nix` immediately.”** Real acknowledged debt, but lower leverage than current security/correctness failures and already partially underway through `flake-parts/packages/`.
- **“Make local Mac `just check` equivalent to Linux.”** Rejected: the project already documents remote Linux execution as the Mac workflow; no concrete breakage beyond that accepted boundary was shown.
- **“Create a generic systemd ExecStart-resolves check.”** Previously rejected in `docs/plans/2026-06-21-improve-audit.md`: interpolated store paths already eval, and the real historical failure class was invalid flags, not missing binaries.

## Audit coverage limits

This was a standard, hotspot-weighted audit across correctness, security, performance, tests, architecture, dependencies, DX, docs, and direction. It did not:

- decrypt or inspect secret values;
- operate against remote production hosts;
- run live tailnet, OAuth-client, backup, or replication journeys;
- audit upstream package source or every imported third-party skill body;
- read every historical plan/spec/report line by line.

Each implementation plan names the missing live verification required before its status can become `DONE`.
